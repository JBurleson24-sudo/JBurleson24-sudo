TEST METHODS
Whole application actions were timed with a phone stopwatch using a Release
build started with Ctrl+F5. Method timings used System.Diagnostics.Stopwatch
with a Release build started with F5 and the debugger attached.
All method times below are milliseconds (ms). Whole action times are seconds.
The median is the middle value after sorting three trial results.

1. DATABASE STARTUP BEFORE OPTIMIZATION

Operation                       Time (ms)
InitializeDatabase                 287.45
SeedDatabase                         1.50
ImportInventory                      1.27
ImportInventoryImages                1.78
Total                              292.00

This baseline contains one Release run.

2. DATABASE STARTUP AFTER SCHEMA CHECK REFACTOR

Operation                       Run 1      Run 2      Run 3     Median
InitializeDatabase             105.02     101.44     100.54     101.44
All four startup calls         108.31     104.98     104.33     104.98

The change reads the Orders column list once and reuses it for both column
checks. SQLite loading, caching, and run variation also affect startup.
The full observed reduction cannot be attributed to this code change.

8. MEDIAN COMPARISON OF WHOLE APPLICATION ACTIONS

Action                          Before (s)  After (s)  Measured reduction
Startup to usable login screen        3.00       1.40               53.3%
Manager Inventory load                0.68       0.65                4.4%
Returns order lookup                  0.43       0.19               55.8%

Measured reduction = (before median - after median) / before median x 100.
Phone reaction time limits precision, especially for subsecond operations.
Manager Inventory and Returns were not directly optimized during these
changes. Their timing differences include test variation.

9. MEMORY COMPARISON DURING PRODUCT BROWSING

Task Manager metric: Commit size, reported in K.
Procedure: Release without debugging, select the first ten games five times,
then wait ten seconds before recording the second reading.

Version                         After launch  After 50 selections  Increase
Original image handling             42,376 K             53,436 K  11,060 K
Resized and disposed images         23,356 K             27,804 K   4,448 K

Observed memory growth was 6,612 K lower, or 59.8% lower in this single test.
This comparison was recorded before images were changed to load on demand.
Commit size covers the process and does not isolate image allocations.
